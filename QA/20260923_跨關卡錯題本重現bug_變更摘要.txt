【影響範圍】

  程式位置一：js/sync-logic.js
  函式：mergeWrongBooks(localBook, cloudBook, localResolvedAt, cloudResolvedAt)
  說明：雲端同步時合併本機與雲端的錯題本清單。
  問題：原邏輯為純聯集（union）合併，只要某筆錯題「曾經」出現在
        cloudBook 或 localBook 任一邊，就一定會被保留在合併結果中，
        完全沒有處理「某一邊已經刻意刪除（訂正完成）」的情況。

  修改前：
    export function mergeWrongBooks(localBook = [], cloudBook = []) {
      const map = new Map();
      for (const entry of [...(cloudBook || []), ...(localBook || [])]) {
        const key = `${entry.unitId}::${entry.questionId}`;
        const existing = map.get(key);
        if (!existing || (entry.date || "") >= (existing.date || "")) {
          map.set(key, entry);
        }
      }
      return Array.from(map.values());
    }

  修改後：
    export function mergeWrongBooks(
      localBook = [],
      cloudBook = [],
      localResolvedAt = {},
      cloudResolvedAt = {}
    ) {
      const resolvedAt = mergeResolvedAt(localResolvedAt, cloudResolvedAt);
      const map = new Map();
      for (const entry of [...(cloudBook || []), ...(localBook || [])]) {
        const key = wrongKey(entry);
        const existing = map.get(key);
        if (!existing || entryTimestamp(entry) >= entryTimestamp(existing)) {
          map.set(key, entry);
        }
      }
      for (const [key, entry] of map.entries()) {
        if (resolvedAt[key] && resolvedAt[key] >= entryTimestamp(entry)) map.delete(key);
      }
      return Array.from(map.values());
    }

  程式位置二：js/sync-manager.js、js/cloud-sync.js
  函式／區塊：ensurePushSubscription / 登入時 fetchCloudState+mergeState+replaceState 流程
  說明：觸發根因的路徑——practice.html 切換關卡是整頁導覽，每次都會重新執行
        sync-manager.js，若前一頁的 push 尚未完成就導覽離開，下一頁的
        pull 會抓到舊版雲端資料，被原 mergeWrongBooks 的聯集邏輯復活。
  異動：同頁 push 改為 Promise queue 依序執行；雲端寫入改用 Firestore
        transaction，在 transaction 內讀取最新雲端狀態、合併後再寫回，
        避免不同頁面或裝置整份互相覆蓋。登入 pull 加入 authGeneration 與
        UID 檢查；成功與失敗分支都需通過檢查，避免舊帳號延遲回應覆寫目前
        使用者的資料或同步狀態。

  程式位置三：js/state-shape.js、js/storage.js
  函式／區塊：emptyProgress / normalizeLearningState / recordAnswer / resetState
  說明：保存錯題事件時間與訂正刪除事件。
  異動：wrongBook entry 新增 updatedAt 與唯一 eventId；每個教材版本新增
