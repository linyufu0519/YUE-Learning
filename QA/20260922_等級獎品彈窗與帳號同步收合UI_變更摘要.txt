【根因與設計】
- 等級獎品清單直接展開在首頁會佔用大量版面（10 個里程碑項目），且與「每日任務與獎勵」
  卡片的視覺重心（今天要做什麼）互相干擾，因此改為「入口按鈕＋彈出視窗」模式，符合
  漸進式揭露（progressive disclosure）原則：預設只顯示最重要的每日任務，等級獎品這種
  「偶爾查看」的內容收在點擊後才出現的 modal 中。
- 帳號同步表單在「已登入且已同步」狀態下，主要資訊只剩「目前是誰、上次同步是什麼時候」，
  完整的 Email/密碼輸入欄位、註冊按鈕在此狀態下已無意義，長期佔用版面；但同步過程中
  會頻繁在 syncing/synced 之間切換（每次答題都會觸發一次背景同步），若直接依 mode 即時
  決定顯示精簡或完整表單，畫面會不斷「展開⇄收合」閃爍。因此新增 `hasSyncedOnce`
  （是否已經同步成功過一次）與 `manualExpanded`（使用者是否手動展開）兩個狀態，
  只有在「第一次尚未同步成功」「未登入」「未設定 Firebase」「同步錯誤」時強制顯示
  完整表單，其餘情況下維持使用者上次的收合/展開選擇，避免閃爍且符合安全性要求
  （錯誤/未登入絕對不可被誤縮到看不到操作入口）。
- 兩者的「何時該顯示什麼」都抽成 `js/ui-logic.js` 的純函式（`computeAccountPanelState`、
  `nextAccountPanelFlags`、`getNextMilestoneGap`、`maskEmail`），不觸碰 DOM，方便在
  Node 測試中窮舉各種狀態組合；`js/home.js` 只負責依據這些函式的回傳值搬動 CSS class /
  hidden 屬性與文字內容，維持既有專案「純邏輯與 DOM 渲染分離」的慣例（沿用自
  `js/logic.js`、`js/rewards.js`、`js/sync-logic.js` 的既有作法）。
- Email 遮蔽只保留前兩碼＋星號＋完整網域（例如 `pa****@mail.com`），避免完整帳號直接
  暴露在畫面上，同時仍可讓家長辨識是哪個帳號。
- 「最近同步時間」透過在 `js/sync-manager.js` 每次成功同步（`mode: "synced"`）時額外
  記錄 `lastSyncedAt`（ISO 字串，僅存在於執行期的記憶體狀態物件，不寫入 localStorage/
  Firestore），首頁讀取後用 `toLocaleString("zh-TW")` 顯示，不影響既有同步/合併邏輯。

【修改檔案】
1. js/ui-logic.js（新增）
   - `maskEmail(email)`：遮蔽 Email 帳號名稱。
   - `computeAccountPanelState({mode, hasSyncedOnce, manualExpanded})`：計算精簡卡片／
     完整表單的顯示狀態（`showCompact`／`showForm`／`showCollapseButton`／`signedIn`）。

【相容性確認】
- 未修改任何 localStorage/Firebase 資料結構、`rewards.js`／`storage.js`／`sync-logic.js`
  的合併與持久化規則；本輪變動全部集中在「首頁如何呈現既有資料」的 UI 層。
- `js/parent.js` 完全未修改，家長頁的完整等級獎品清單與「確認領取」按鈕（含 8888 密碼
  授權）維持原樣。
- `lastSyncedAt` 只存在於 `sync-manager.js` 執行期的記憶體狀態物件中，不寫入
  localStorage 或 Firestore，重新整理頁面後會重新走一次 `initSync()` 流程，不影響既有
  同步/合併行為。
- 首頁在 JS 尚未執行完成前（例如載入極慢或 JS 被封鎖的極端情況），原始 HTML 預設值為
  「精簡卡片 hidden、完整表單顯示、彈出視窗 hidden」，符合「未登入/未設定時完整表單可見、
  獎品清單不會誤展開」的安全預設。
